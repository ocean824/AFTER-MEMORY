# AFTER//MEMORY — Game Design Bible

## Identity
Atmospheric horror/action exploration centered on colossal entities and recovering fragmented memories. Scale, dread, ambiguity and consequence matter more than constant combat.

## Core loop
Enter haunted landscape → investigate environmental clues → evade/survive lesser threats → recover memory fragment → world/perspective changes → discover colossus → traversal/puzzle/confrontation → decide what memory/truth to preserve → consequence.

## Memory system
Fragments are playable/interactive evidence, not collectible lore dumps. Recovering, altering or refusing memories can change spaces, character understanding, routes and endings. Time Travel System may accelerate implementation if it maps cleanly to canonical state rules.

## Colossi
Each colossal encounter is a level/boss hybrid with observation, traversal, vulnerability discovery and high-risk confrontation. Boss AI/animation/BlackMoon/Sci-Fi Myth assets are prototyping resources.

## Horror
Threat is built through sound, visibility, scale, pursuit, uncertainty and resource pressure. Bodycam/Black Eye/Post-Process stack is OPTIONAL stylistic tooling for specific memories/segments, not mandatory whole-game presentation.

## Combat
Limited and consequential; Flexible Combat may support encounters but game identity must not drift into generic action RPG.

## V1→V3
V1 proves one region, memory-state system, horror loop and one full colossus. V2 expands landscapes/memory branches/colossi. V3 complete nonlinear campaign/endings/endgame secrets and AXIOM-native implementation.
